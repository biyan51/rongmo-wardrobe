# 溶墨的衣柜

免登录的个人穿搭网页，以已有衣服和清爽学院风为主。初始含 31 项衣柜记录（包含在家暂不参与轮换的马丁靴）及 24 套原有方案，另外可按标签生成试穿参考组合。

## 第一次开启网页

上传完成后，打开仓库 Settings → Pages。在 Build and deployment 中选择 Deploy from a branch，分支选 main，目录选 /(root)，保存。发布成功后，网站地址为 https://biyan51.github.io/rongmo-wardrobe/ 。是否能在实际网络下稳定直连仍需验证。

## 日常使用

选一件或跨类别选多件衣服，再按季节、场景和风格筛选；随机推荐遵守筛选条件。在途、在家或暂停的单品默认不参与推荐，可手动勾选查看。

穿搭记录仅保存在当前浏览器 localStorage，不上传 GitHub 或云端，不会跨设备同步。清除浏览器数据可能丢失记录，请在“使用与备份”里导出 JSON。

## 衣柜数据独立更新

单品、状态、照片地址、搭配方案和规则位于 data/wardrobe.json，与界面代码分开。Pages 启用后，仓库修改会触发发布，前端重新读取最新文件。普通访问者不能修改仓库。用户在聊天中授权且助手连接此仓库后，可由助手更新这个 JSON；这不是无人值守更新，没有配置定时任务。

更新时先读取最新版，保留未知用户内容；不要覆盖整个衣柜为初始清单。每次更新递增 revision，并设置 updatedAt。已有方案需单独编辑，修改单品标签不会自动重写已有方案。图片可放在 photos/ 并使用站内相对路径。当前没有上传实物照片，服装图形均为颜色示意图。

规则组合不分析身材、实物面料或实时天气，只是试穿起点。原有方案与规则组合会分别标记。

## 页面和源码

index.html、app.js、app.css、favicon.svg 是已构建页面；src/、lib/、build.mjs 和 package.json 用于后续维护。仅更新 JSON 不需要重建页面。如修改界面，安装依赖后执行 npm run build，再提交更新后的 app.js。

本站和仓库公开。noindex 仅请求搜索引擎不要收录，不是保密措施。不要把密码、密钥、私人穿搭记录或其他敏感资料放进仓库。

## 2026-10-22 天气与定位

- 在“今天穿什么”点击“获取当前位置”后才申请浏览器授权；也可手动搜城市并选择结果。打开网页不自动定位，不持续跟踪。
- 展示摄氏度、体感、当天高低温、最高降水概率、天气模型数据的当地时间，并给出独立的穿衣参考；不会自动改动筛选或已选单品。
- GitHub 静态版直接请求 Open-Meteo，无需账户或密钥。发送前将经纬度取整至小数点后两位；位置只在本页面内存中保留，不写入 localStorage、衣柜 JSON 或穿搭记录。网页中已说明服务商并署名 Open-Meteo / GeoNames。
- 定位拒绝、超时或天气服务不可达时仍可正常使用衣柜。数据源为天气模型，非现场实测；服务及具体网络可用性不作保证。

## 2026-10-23 区县定位

- 点击定位时申请一次较高精度的位置，发送前仍取整到小数点后两位；用 Photon / OpenStreetMap 补充城市与附近区县名。不保存定位历史、不持续跟踪。
- 显示“南京市 · 玄武区附近”等参考标签；地图数据缺失、区界或设备定位不准时可能偏差，无法识别时明确提示。区县服务失败独立于天气服务。
- 手动地区搜索在 GeoNames 无结果时补查 Photon 行政地区，支持“杨浦”等区名；仅点击查询，不做自动补全或后台轮询。页面包含数据署名。

## 2026-10-23 天气连接修复

共享天气读取增加 HTTP 错误分类、独立请求超时和取消保护。Sites 版本在天气代理发生网络／服务错误时自动回退到同一 Open-Meteo 服务直连一次；400/401/403 或用户取消不会触发回退。坐标仍先取整，未增加定位权限或新的天气服务商。GitHub 静态版保持直接读取天气，不访问 Sites 私有数据。
